\section{HEP Packaging Coordination}\label{sec:hep-packaging-coordination}

Based on evidence from work by the LHCb collaboration to use conda-forge packages of LHCb software for experiment use, the \href{https://hep-packaging-coordination.github.io/.github/}{HEP Packaging Coordination} community project~\cite{hep_packaging_coordination} on GitHub was created with the goal of creating multi-platform builds of HEP software for public use on conda-forge.
As of September 2026, HEP Packaging Coordination has over 120 packages from the broader HEP software community packaged and distributed through conda-forge with contributions from members of the ATLAS, CMS, LHCb, LEGEND, Belle II, SHiP, and DUNE experimental collaboration communities, as well as contributions from the Scikit-HEP, IRIS-HEP, ROOT Team, DIRAC, and CEDAR software organizations/collaborations, and from the HEP theory and phenomenology communities.
HEP Packaging Coordination aims to make the process of distributing robust and performant packages of HEP software a more streamlined community effort that also reduces the maintainer burden on individual software project maintainers by coordinating efforts and leveraging the conda-forge community resources and public cyberinfrastructure.
As an example, through leveraging the conda-forge migration system and community maintainership, the majority of HEP Packaging Coordination conda-forge packages that have any dependency on Python will have validated builds that support Python 3.15 before it is released on 1 October 2026.
This allows for the HEP Packaging Coordination community to lead software enhancement adoption without being constrained by operating-system-specific restrictions or concerns of breaking support across the broader HEP software ecosystem, as all existing packages on conda-forge are immutable.
Through engagement with the conda-forge community, HEP Packaging Coordination is also working to support the sometimes bespoke needs of the HEP software community.
Collaborations with the ROOT Team have been particularly fruitful, resulting in fewer LLVM-related patches in the ROOT conda-forge feedstock and in build enhancements being integrated into the main \texttt{root\_base} conda-forge conda package.
